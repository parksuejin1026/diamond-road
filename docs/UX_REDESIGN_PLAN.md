# Diamond Road 진행 UX 재설계

작성: 2026-11-04. 기준: 사용자의 순차 진행 지시, `modify_desi.md`, 실제 참고 게임 플레이 기록.

## 최신 변경 요구사항과 적용 상태

사용자의 후속 지시가 아래 이전 초안보다 우선한다. 시즌은 한 번에 자동 진행하고 직접 조작과 커리어 이벤트를 제거한다. 홈·시즌·선수·기록 하단 탭으로 나눈다. 홈에는 초상화·이름·소속·나이·OVR·전년 대비 변화와 통산 요약을 둔다. 타자는 경기·타율·홈런·타점, 투수는 경기·평균자책·승리·탈삼진을 기본 요약으로 사용한다.

장기 목표는 **시즌 MVP 누적 12회 수상**으로 해석한다. 앞선 답변의 '서로 다른 MVP 12종' 제안은 사용자 요청과 맞지 않아 채택하지 않는다.

후속 구현 대상은 아시안게임, 16세→고교→드래프트→프로 계약/FA/잔류, 매 시즌 집중 육성, 수비와 세부 포지션, 성적에 따른 투수 보직, 시즌 전 아이템, 명성을 반영한 연봉 협상, 시즌 말 무작위 성장이다. 실제 KBO 계약·FA 및 국제대회 규칙은 공식 자료로 확인한 다음 게임의 간소화 범위를 명시한다.

현재 코드 반영: 하단 4탭, 도트 홈과 통산 요약, 네이비·골드 토큰과 한글 도트 글꼴, 전체 시즌 자동 진행, 이벤트 없는 진행 옵션, 이전 수동 중단 저장을 자동 타석 처리로 재개하는 경로. 시즌 전 기존 훈련에는 수비가 포함되어 있다. 아시안게임·계약 개편·보직·아이템·성장 개편 및 3단계 선수 생성은 아직 미적용이다. 공개 GitHub Pages에는 아직 배포하지 않았다.

검증: TypeScript 검사, 기존 엔진 테스트 32개, 정적 빌드 통과. 브라우저 시나리오는 모바일 홈/자동 시즌/저장 복원, 이전 타자·투수 중단 저장 복구, 계약 후 다음 시즌, 고교 3년/드래프트/프로 입단, 조기 은퇴를 검사했다. 첫 실행 5개 통과 후 은퇴 화면의 탭 기대값을 수정하고 해당 시나리오 재실행 통과(총 6개 확인). 360×800 홈 스크린샷은 로컬 `artifacts/redesign-mobile-home.png`에 저장했다. 이전 직접 조작 전용 E2E는 자동 진행 복구 시나리오로 교체했다.

## 연구 상태

참고: https://kickru.com/

10회 커리어 플레이와 발롱도르 총 2회 수상을 목표로 진행 중이다. 도중에 멈춘 탐색 플레이는 완료 횟수에 포함하지 않는다. 후보 순위·수상 애니메이션·시즌 결산에 같은 수상이 반복 표시되는 경우 하나의 수상으로 센다. 저장 데이터·능력치·난수·시계 등을 수정하지 않고 실제 화면의 선택과 서명·관전·건너뛰기 기능만 사용한다. 실험용 커리어를 공개 랭킹에 게시하지 않는다.

원시 화면 기록·선택 기록·스크린샷은 로컬 `artifacts/reference-study/`에 보관한다. 타 게임의 원문 화면과 이미지 자산은 제품에 포함하지 않는다. 완료 결과표는 플레이 종료 후 이 문서에 추가한다.

## 현재까지 확인한 차이

1. 생성은 정체성 → 스타일 → 집중 육성 → 최종 카드로 분리된다. 설정을 한 페이지에 늘어놓지 않는다.
2. 시즌 진행 중에는 경기 결과를 따라가는 것이 중심이고, 결승전은 조작 없이 중계를 본다. 시즌 중계와 커리어 선택의 리듬이 분리된다.
3. 결산은 성장·출전·활약을 먼저 보여주고 대회 결과와 개인상, 반응이 뒤따른다. 다음 해 버튼이 아니라 한 시즌을 되돌아보는 시간이 있다.
4. 결산 확인 후 홈에 필요한 선택이 모인다. 전환점, 계약·임대, 육성 방향이 다음 시즌의 실제 역할과 연결된다.
5. 큰 구단의 벤치와 작은 구단의 주전은 다른 경험이다. 최고 연봉만으로 선택하면 성장·출전에서 손해를 볼 수 있다.
6. 후보 순위와 실제 개인상 수상은 다르다. 실제 발롱도르 수상은 별도 연출로 드러나며 은퇴 기록에서 다시 확인된다.
7. 은퇴는 통산 숫자만 보여주지 않는다. 주요 시즌과 구단 이동, 트로피, 선수의 커리어 유형을 되돌아본다.

## 야구판의 기본 순환

`홈의 다음 할 일 → 시즌 준비 → 자동 시즌 관전 → 성장·성적 결산 → 홈 → 전환점/출전 역할/진로 선택 → 다음 시즌`

고교는 `고1 → 고2 → 고3 → 드래프트`, 프로는 `입단 → 벤치·2군·로테이션 경쟁 → 전성기 → 계약·이적 → 노쇠·은퇴`가 이 순환에 연결된다. 기존 실제 학교 104팀과 KBO 10구단, 기록·저장·경기 엔진을 활용한다.

### 홈

- 현재 소속·나이·역할·OVR과 지난 시즌 변화가 중심이다.
- 다음에 해야 할 일은 한 가지 주 행동으로 안내한다.
- 전환점·계약·드래프트 등 선택이 필요한 항목을 별도 카드로 제시한다.
- 순위표·통산 기록·전체 능력치·계약 이력을 모두 홈에 펼쳐 놓지 않는다.
- 홈·소식·시즌·선수·기록으로 정보를 나누되 진행 상태는 공통 저장 데이터를 따른다.

### 선수 생성

사용자 MD의 3단계를 따른다.

1. 선수의 탄생: 이름, 타자/투수 선택.
2. 나의 야구 인생: 지역과 학교 검색, 플레이 스타일. 학교는 검색 결과와 선택된 학교를 명확히 나누고 104개 버튼을 좁은 상자에 나열하지 않는다.
3. 커리어 시작: 집중 육성와 관전 설정, 최종 선수 카드, 시작 버튼.

데스크톱은 선수 프리뷰와 현재 단계의 선택 화면을 나란히 두고, 모바일은 프리뷰를 간결하게 접어 현재 선택을 우선한다. 이전 단계로 돌아가도 선택은 보존한다.

### 시즌 관전

- 직접 타격·투구, 스페이스 타이밍, 구종·목표 구역·제구 게이지는 제거한다.
- 사용자는 경기 결과를 조작하지 않는다. 관전 일시정지·배속·결과로 건너뛰기는 가능하다.
- 계절·주차·경기·실제 점수와 개인 기록의 변화를 도트 구장과 중계로 보여준다.
- 중계 장면은 실제 엔진 결과에서 만든다. 연출을 위해 득점이나 개인 기록을 추가하지 않는다.
- 시즌 중 선택이 매번 진행을 막는 현 구조는 재검토한다. 연간 전환점과 오프시즌 진로를 정해진 단계에서 처리하고 다음 시즌에 어떤 효과가 있는지 알려준다.
- 중단·새로고침·건너뛰기가 중복 경기나 중복 기록을 만들지 않아야 한다.

### 시즌 결산

1. 올해의 핵심: 출전, 타격/투구 성적, 팀 성적, 성장 전후 OVR.
2. 집중 육성 능력치와 역할 변화.
3. 주말리그·전국대회 또는 정규시즌·포스트시즌 결과.
4. 실제 수상일 때만 별도 보상 연출.
5. 올해의 이야기와 다음 선택으로 이어지는 근거.

세부 누적 기록은 별도 기록 화면에서 본다. 선택의 효과는 단순한 `+2` 버튼보다 출전 기회·성장·건강·명성의 변화와 연결해 설명한다.

### 계약·진로

제안에는 구단, 기간·연봉, 예상 역할·경쟁 정도, 팀 성적을 비교해 보여준다. 첫 프로 계약에는 특별한 연출을 두고 매년 반복 계약에 불필요한 조작을 강요하지 않는다. 거절·잔류도 명확한 선택이다. 고교 성장과 드래프트, 프로 통산은 분리해 보존한다.

### 은퇴

통산 성적, 최고 시즌, 개인상·우승, 소속팀 변화, 기억할 만한 순간을 한 선수의 이야기로 정리한다. 결과가 달라질수록 다시 시작할 이유가 생겨야 한다.

## 도트 디자인 적용

색상은 사용자 MD의 네이비 `#0B1220`, 표면 `#111C2E`, 골드 `#F4B950`, 성장 `#36C9A2`를 토큰으로 사용한다. 골드는 주 행동과 보상에 제한한다.

- 야구장: 320×180 기준, 외야·흙·베이스·관중석·전광판·조명·도시 배경을 개별 픽셀 요소로 제작.
- 선수: 48×64 기준의 자체 제작 픽셀 캐릭터. 모자·유니폼·글러브·배트와 역할별 자세를 분리.
- 관전 동작: 자동 투구·스윙·타구·득점·교대 애니메이션. 입력 판정은 없음.
- 선수 카드: 이름·역할·OVR·학교·스타일·주요 능력치가 실시간으로 갱신되는 재사용 컴포넌트.
- UI: 8px 간격, 48px 이상 주요 버튼, 절제된 픽셀 테두리, 읽기 쉬운 한글 픽셀 글꼴과 큰 수치.
- 320px부터 1440px까지 검증하고 `prefers-reduced-motion`을 지원.

글꼴만 바꾸거나 모든 요소를 네모로 만드는 것으로 도트 디자인을 대신하지 않는다. 그래픽은 별도 원본으로 제작하고 타 게임의 선수·구장·아이콘을 사용하지 않는다.

## 구현 및 검증 순서

1. 실제 10회 플레이 결과와 수상 근거 정리.
2. 홈→시즌→결산→진로의 상태 전이와 화면별 주 행동 확정.
3. 수동 미니게임의 진입·입력 UI 제거, 기존 중단 저장의 자동 재개 호환.
4. 디자인 토큰·픽셀 구장·선수 카드와 3단계 생성 화면 제작.
5. 자동 관전과 결산 화면 연결. 그 후 드래프트·계약·은퇴 화면 확장.
6. 새 커리어 고교 3년→프로→은퇴, 기존 저장 복구, 관전 건너뛰기·새로고침·중복 입력, 모바일·키보드 검사.
7. 검증 결과와 구현 범위를 보고하고 배포 상태를 명확히 구분.
